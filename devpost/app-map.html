JobXray app map

A snapshot of how JobXray works, taken from the code at commit 4d068b3 and later wrap-up edits. The code can drift from this map; trust the code.

What it is

JobXray investigates a job or internship offer before you pay, apply, or share anything. You give it pasted messages, a link to a posting, or a screenshot. It returns Proceed, Verify First, or Stop, with the evidence behind it.

Three main pieces:

  • The web page (Next.js, frontend/): the paste box, the live progress scanner, and the result report.
  • The investigation server (FastAPI, backend/): runs the steps, keeps each investigation in memory, and answers polling.
  • Outside services: OpenRouter free models (reading and observing) and the company's own website (fetched with Scrapling).

Reference route through the code

A reference route for later, not a tour you completed. Search for the names in quotes.

  1. Where the model's reading gets checked: backend/app/investigation/extract.py, search def check_quotes. Quotes that aren't really in your text are dropped, and a "we never charge any fee" sentence is reclassified so it can never count as a payment request (backend/app/evidence/no_fee.py).
  2. Where the verdict is decided: backend/app/evidence/status.py, search def opportunity_status and def decide. Verified, Unverified, Unknown and Contradiction come from what was observed, and the decision comes from fixed rules, not from the model's opinion.
  3. Where the whole sequence runs: backend/app/investigation/pipeline.py, search def run_investigation and def check_official_sources. This is where calls 1–4, the page fetches and the budgets come together.

To change this, start here

  • Decision wording or next steps: NEXT_STEP and SEVERITY in backend/app/evidence/status.py.
  • What the model is told: the prompt files in backend/app/prompts/ (extract.md, plan.md, observe.md, challenge.md, transcribe.md).
  • Limits (characters, fetches, model calls): backend/app/config.py.
  • Which free models are used: OPENROUTER_MODEL and VISION_MODEL in backend/.env.
  • The look and motion: frontend/app/globals.css and the beam in frontend/components/XrayBackdrop.tsx.
  • The saved example: re-save with python -m scripts.save_example <file> from backend/.

A practice to reuse

Let the model observe; let code decide. In JobXray the model only extracts claims and reports what pages say, with quotes. Fixed rules in status.py turn that evidence into a verdict.

What it caught: in a live run, the model labelled "Microsoft never charges candidates any fee" as a fee, which made a legitimate posting STOP. Because the verdict logic was separate and visible, the faulty input was easy to pinpoint. The fix is a deterministic guard (backend/app/evidence/no_fee.py) plus a regression test, test_no_fee_statement_is_never_a_payment_request in backend/tests/test_status_rules.py.

On another project: when an agent has to judge something, keep the model's job small and checkable, put the verdict in code you can test, and run a few real examples before trusting it. Saved test fixtures prove the rules; only live runs prove the model's inputs.

Run it again

Start both servers 
cd backend
.venv/Scripts/python -m uvicorn app.main:app --port 8000

cd frontend
npm run dev

Open http://localhost:3000. Tests: cd backend then .venv/Scripts/python -m pytest -q.
